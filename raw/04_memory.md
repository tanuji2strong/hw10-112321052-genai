# 04. 記憶機制 (Memory)

想像你聘請了一位非常聰明的新助理，但他患有嚴重的失憶症，只要你離開辦公室五分鐘，他就會忘記你剛才交代過的所有事情。這樣的助理顯然是不合格的。

對於 AI Agent 來說也是一樣。為了提供連貫、個人化的服務，Agent 必須擁有 **記憶機制 (Memory)**。我們通常將其分為「短期記憶」與「長期記憶」。

## 短期記憶：Context Window (脈絡視窗)

短期記憶就像是你大腦中的「工作記憶」或電腦的「記憶體 (RAM)」。在 AI 的世界裡，這被稱為 **Context Window (脈絡視窗)**。

*   **運作原理**：當你在跟 Agent 對話時，系統會把你剛剛說過的每一句話都記錄下來，並在每一次你發送新訊息時，把「過去的對話紀錄 + 你的新問題」整包丟給 LLM 重新閱讀。因為 LLM 閱讀了剛剛的對話，它就「想起來」你們在聊什麼了。
*   **限制**：Context Window 是有容量限制的（我們通常用 Token 來計算容量）。如果你們聊了三天三夜，對話紀錄太長，超出了視窗限制，Agent 就會被迫「忘記」最一開始聊天的內容（就像電腦 RAM 被塞滿一樣）。

## 長期記憶：向量資料庫與 RAG

為了彌補短期記憶容量有限的問題，並讓 Agent 能夠記住幾個月前甚至幾年前的資訊，我們需要「長期記憶」。這通常會用到 **向量資料庫 (Vector Database)** 與 **RAG (檢索增強生成)** 技術。

長期記憶就像是一個超大型的數位圖書館或檔案櫃。

*   **存入記憶**：當你告訴 Agent 一個重要的個人資訊（例如：「我對花生過敏」、「我家狗叫小白」），系統會將這句話轉換成數學向量（一串數字），並存進長期記憶庫中。
*   **提取記憶 (RAG 機制)**：
    **RAG (Retrieval-Augmented Generation)** 的意思是「先檢索資料，再生成回答」。
    當你幾個月後對 Agent 說：「幫我訂一個蛋糕慶祝小白的生日。」
    Agent 會先在它的記憶庫中進行搜尋（Retrieval），找出含有「小白」與「飲食禁忌」的相關筆記。它找到了「小白是狗」以及「你對花生過敏」的紀錄。接著，Agent 才會生成回答（Generation）：「沒問題！我來幫小白（狗狗）找一間寵物蛋糕店，而且會特別交代店家絕對不能沾到花生！」

## 短期與長期記憶的完美搭配

一個成熟的 AI Agent 會同時使用這兩種記憶：
用 **Context Window (短期)** 來維持當下這半小時聊天的順暢度；
用 **RAG (長期)** 來隨時調閱過去的重要筆記。
這讓 Agent 聽起來就像一個認識你多年的老朋友！
