開場

從聊天到會做事：為什麼需要 agent？

  • 新的基礎模型能力，讓開發者有機會做出能替我們辦事的自主 agent。“These new capabilities make it finally possible to develop autonomous, intelligent agents to act as our assistants, coworkers, and coaches.”s06
  • Agent 由 LLM 自己決定流程與工具使用。“Agents, on the other hand, are systems where LLMs dynamically direct their own processes and tool usage, maintaining control over how they accomplish tasks.”c01-what-is-an-agent
  • 沒有外部工具也能算是 agent，但能力會受限。“A system doesn’t need access to external tools to be an agent. However, without external tools, the agent’s capabilities would be limited.”c01-what-is-an-agent

什麼是 agent？

概念

LLM 是核心，再加上三個元件

  • LLM 是 agent 的大腦，再加上規劃、記憶與工具使用三個元件。“In a LLM-powered autonomous agent system, LLM functions as the agent’s brain, complemented by several key components:”s03
  • 三個元件中的工具使用，讓 agent 能呼叫外部 API 取得缺少的資訊。“The agent learns to call external APIs for extra information that is missing from the model weights”s03
  • 這些能力合稱為增強型 LLM（augmented LLM），是 agent 系統的基本積木。“The basic building block of agentic systems is an LLM enhanced with augmentations such as retrieval, tools, and memory.”c02-augmented-llm

概念

workflow 與 agent 的差別

  • Workflow 是預先寫好程式路徑，LLM 與工具照順序被編排。“Workflows are systems where LLMs and tools are orchestrated through predefined code paths.”c03-workflow-vs-agent
  • Agent 則是 LLM 動態決定自己的流程與工具使用。“Agents, on the other hand, are systems where LLMs dynamically direct their own processes and tool usage, maintaining control over how they accomplish tasks.”c03-workflow-vs-agent
  • 定義清楚的任務適合 workflow，需要彈性時才適合 agent。“When more complexity is warranted, workflows offer predictability and consistency for well-defined tasks, whereas agents are the better option when flexibility and model-driven decision-making are needed at scale.”c03-workflow-vs-agent

概念

工具使用：模型請求，程式執行

  • 模型自己不執行任何東西，它只發出結構化的請求。“The model never runs anything on its own.”c04-tool-use-loop
  • 工具由應用程式（或 Anthropic 的伺服器）執行，結果再回到對話中。“It emits a structured request, your code (or Anthropic’s servers) runs the operation, and the result flows back into the conversation.”c04-tool-use-loop
  • Claude 決定何時、如何呼叫工具；它只看得到工具定義（schema）與回傳結果，看不到你的程式碼。“Claude never receives your implementation; it only receives the schema you provided and the result you returned.”c04-tool-use-loop

概念

工具使用循環：一來一往直到完成

  • 模型要求工具、程式執行、結果送回，然後模型再繼續。“Make a second request to the model with the tool output”c04-tool-use-loop
  • 程式持續執行工具並把結果送回 Claude，直到 stop_reason 不再是 tool_use。“keeps running tools and feeding results back until”s07
  • 多步驟任務需要迴圈：Claude 可能先建立活動、讀取確認，再建立另一個。“Ring 1 assumed Claude would call the tool exactly once. Real tasks often need several calls: Claude might create an event, read the confirmation, then create another.”c04-tool-use-loop

概念

規劃：拆解任務，並從錯誤中反思

  • 規劃包含把大任務拆成子目標，讓複雜任務可以處理。“Subgoal and decomposition: The agent breaks down large tasks into smaller, manageable subgoals, enabling efficient handling of complex tasks.”c05-planning
  • 反思讓 agent 從過去的行動中學習，改進之後的步驟。“Reflection and refinement: The agent can do self-criticism and self-reflection over past actions, learn from mistakes and refine them for future steps, thereby improving the quality of final results.”c05-planning
  • 規劃與執行應該分開：先產生計畫，計畫通過驗證後才執行。“To avoid fruitless execution, planning should be decoupled from execution. You ask the agent to first generate a plan, and only after this plan is validated is it executed.”c05-planning

概念

記憶：短期記憶與長期記憶

  • 作者認為，上下文中的 in-context learning 可以視為短期記憶。“Short-term memory: I would consider all the in-context learning (See Prompt Engineering) as utilizing short-term memory of the model to learn.”c06-memory
  • 短期記憶受上下文視窗長度限制，因此很有限。“It is short and finite, as it is restricted by the finite context window length of Transformer.”c06-memory
  • 長期記憶是外部向量資料庫，需要時用快速檢索取回。“Long-term memory: This provides the agent with the capability to retain and recall (infinite) information over extended periods, often by leveraging an external vector store and fast retrieval.”c06-memory

概念

ReAct：推理與行動交錯

  • ReAct 讓 LLM 以交錯的方式，同時產生推理與行動。“we explore the use of LLMs to generate both reasoning traces and task-specific actions in an interleaved manner”c07-react
  • 推理幫助模型規劃與追蹤，行動則讓它取得外部資訊。“while actions allow it to interface with external sources, such as knowledge bases or environments, to gather additional information.”c07-react
  • 這種交錯的做法已成為 agent 的常見模式。“First proposed by ReAct (Yao et al., 2022), interleaving reasoning and action has become a common pattern for agents.”c07-react

誤解

誤解一與二：完全自主？錯誤會累積？

  • 誤解一：agent 是完全自主、不需要人參與的。其實 agent 常從人的指令或討論開始。“Agents begin their work with either a command from, or interactive discussion with, the human user.”m01-agents-are-fully-autonomous
  • 誤解二：每一步都對，最後結果就一定對。步驟越多，錯誤越會累積。“Compound mistakes: an agent often needs to perform multiple steps to accomplish a task, and the overall accuracy decreases as the number of steps increases.”m02-errors-compound
  • 每一步 95% 的準確率，十步後整體會降到 60%。“If the model’s accuracy is 95% per step, over 10 steps, the accuracy will drop to 60%, and over 100 steps, the accuracy will be only 0.6%.”m02-errors-compound
12 / 14
誤解

誤解三：agent 越複雜越好？

  • 誤解三：agent 的流程越多、系統越複雜，就一定越強。“When building applications with LLMs, we recommend finding the simplest solution possible, and only increasing complexity when needed.”m03-more-complexity-is-better
  • 對許多應用，單次 LLM 呼叫加上檢索與範例通常就夠用。“For many applications, however, optimizing single LLM calls with retrieval and in-context examples is usually enough.”s01
  • 成功不在於做出最精密的系統，而在於做出適合需求的系統。“Success in the LLM space isn't about building the most sophisticated system. It's about building the right system for your needs.”m03-more-complexity-is-better
